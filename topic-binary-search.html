02. FORMAL PROBLEM SPECIFICATION & INVARIANTS ACADEMIC CURRICULUM

Binary Search is the quintessential Divide-and-Conquer algorithm for locating the position of a target key \(K\) within a strictly sorted array \(A[0 \dots n-1]\).

Loop Invariant: At the start of every iteration, if key \(K\) exists within array \(A\), it is guaranteed to reside within the index sub-range \([ ext{low}, ext{high}]\).

Algorithm Steps:

  1. Initialize search boundaries: \( ext{low} = 0, ext{high} = n - 1\).
  2. While \( ext{low} \le ext{high}\):
    • Compute probe index: \( ext{mid} = ext{low} + \lfloor rac{ ext{high} - ext{low}}{2} floor\).
    • Match: If \(A[ ext{mid}] == K\), return \( ext{mid}\) (Target found!).
    • Left Sub-Array: If \(K < A[ ext{mid}]\), target cannot reside in right half; set \( ext{high} = ext{mid} - 1\).
    • Right Sub-Array: If \(K > A[ ext{mid}]\), target cannot reside in left half; set \( ext{low} = ext{mid} + 1\).
  3. If \( ext{low} > ext{high}\), return \(-1\) (Target does not exist in array).

03. BRUTE FORCE VS ALGORITHMIC OPTIMALITY STRATEGIC COMPARISON

Searching for a criminal in a New York City phonebook of \(n = 1,000,000\) names using Linear Search takes up to \(1,000,000\) comparisons. Spider-Man's Binary Search eliminates 500,000 possibilities on the very first web zip, trapping any target in at most \(\lfloor \log_2(1,000,000) floor + 1 = 20\) comparisons!

LINEAR SEARCH [O(n)]
Scans every index sequentially.
Worst Case: \(n\) steps.
For \(n = 10^9 \implies 1,000,000,000\) operations (takes ~1 second on 1GHz CPU).
BINARY SEARCH [O(log n)]
Halves search interval on every comparison.
Worst Case: \(\lfloor \log_2 n floor + 1\) steps.
For \(n = 10^9 \implies \le 30\) operations (takes ~30 nanoseconds!).
WHY THIS ALGORITHM WINS:
Binary Search probes the midpoint MID. If the target is greater, the entire lower half is eliminated; if smaller, the upper half is discarded. The search space shrinks by 50% on every probe, finding any channel in <= 20 steps.

04. MATHEMATICAL PROOFS & RECURRENCES KATEX FORMULATION

Recurrence Relation for Binary Search:

\[ T(n) = T(n/2) + c \]

Solving via Master Theorem: Here \(a = 1, b = 2, f(n) = c = \Theta(n^0)\).

\[ n^{\log_b a} = n^{\log_2 1} = n^0 = 1 \]

Since \(f(n) = \Theta(n^{\log_b a})\) (Case 2 of Master Theorem with \(k = 0\)):

\[ T(n) = \Theta(n^{\log_b a} \log^{k+1} n) = \Theta(1 \cdot \log^1 n) = \Theta(\log_2 n) \]

Maximum Number of Comparisons: In the worst case, the search continues until the interval size is 1:

\[ \frac{n}{2^k} = 1 \implies 2^k = n \implies k = \log_2 n \implies \text{Total comparisons} = \lfloor \log_2 n \rfloor + 1 \]

  1. Iteration 1: low = 0, high = 10.
    \( ext{mid} = 0 + (10 - 0) // 2 = 5\).
    Inspect arr[5] = 47.

  2. Now search for \(K = 72\) (Multi-step Trace):
    Pass 1: low = 0, high = 10 \implies mid = 5 (arr[5] = 47). Since \(72 > 47\), set low = 6.
    Pass 2: low = 6, high = 10 \implies mid = 6 + (10-6)//2 = 8 (arr[8] = 72).
    Comparison: \(arr[8] == 72\)? MATCH! Return index 8. (Completed in only 2 comparisons out of 11 elements!).

09. PRACTICAL SYSTEMS DESIGN & REFERENCE IMPLEMENTATION PRODUCTION ARCHITECTURE

1. The Infamous Midpoint Overflow Bug: In 2006, Joshua Bloch revealed that the standard binary search in Java's standard library contained a bug that existed for 9 years: writing mid = (low + high) / 2 overflows a 32-bit signed integer if low + high > 2^{31} - 1, resulting in a negative index and ArrayIndexOutOfBoundsException. The fix is low + (high - low) / 2 or unsigned shift (low + high) >>> 1.

2. Binary Search on Answer / Monotonic Predicates: Binary Search isn't just for arrays! It solves optimization problems where a predicate function \(P(x)\) is monotonic (e.g. 'Can we ship all packages within \(D\) days with capacity \(W\)?'). We binary search over the answer range \([1, \sum W]\) in \(O(\log( ext{range}))\).

3. Lower Bound & Upper Bound: Standard binary search finds any match. C++'s std::lower_bound finds the first index \(\ge K\), and std::upper_bound finds the first index \(> K\), enabling \(O(\log n)\) range counting.

ALGORITHM SPECIFICATION // PYTHON 3 UTF-8 // VERIFIED OPTIMAL 
def binary_search(arr: list[int], target: int) -> int:
    """
    Classic iterative Binary Search with integer overflow protection.
    Returns index of target if found, else -1.
    Time Complexity: O(log n)
    Space Complexity: O(1)
    """
    low = 0
    high = len(arr) - 1
    
    while low <= high:
        # Crucial: prevents integer overflow in fixed-width languages (C++/Java)
        # Instead of mid = (low + high) // 2:
        mid = low + (high - low) // 2
        
        if arr[mid] == target:
            return mid  # Target acquired!
        elif arr[mid] < target:
            low = mid + 1   # Target in right partition
        else:
            high = mid - 1  # Target in left partition
            
    return -1  # Target not in array
